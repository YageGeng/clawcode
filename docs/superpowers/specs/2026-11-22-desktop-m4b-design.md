# Desktop 消息操作、改动标签与按轮次改动（M4b）设计

本文是 M4 的第二个子项目，替换 [M3b 外壳重构设计](./2026-11-21-desktop-shell-redesign-design.md) 第 12 节中「会话树做成右侧面板的一种标签」这一条，并替换该文档第 6.2 节中「改动」标签的布局和加载方式、第 8 节中 `git_diff` 不填 `path` 返回整个工作区 patch 的约定（见第 4 节）。desktop 不做会话树，浏览历史用 [M4a 轨迹视图](./2026-11-21-desktop-trajectory-design.md)。没有被本文提到的部分仍然有效。

本文有三部分：

- **消息操作**（第 3 节）：transcript 消息上的复制、Branch、Fork；
- **「改动」标签重做**（第 4 节）：文件树放左边，diff 按文件懒加载；
- **按轮次改动**（第 5、6 节）：每次运行前后给工作区拍快照，按轮次查看 agent 改了什么。

## 1. 背景与目标

- 后端已经提供 `_clawcode` 扩展方法 `Tree`、`Branch`、`Fork`，desktop 还没有调用。
- 「改动」标签一次取回整个工作区的 patch，上限 2 MiB。改动多时（例如本地有大量未推送的提交）从中间截断，后面的文件完全看不到。
- desktop 看不出 agent 的某一轮改了哪些文件。

目标：

- 在消息上复制原文、编辑之前的提问重新发送、从一条回复分叉出新会话；
- 「改动」标签的行为对齐 T3 Code（调研版本 `f9b19a7f85`）：先列文件，按需加载每个文件的 diff；
- 像 T3 Code 一样，按轮次查看改动，入口在「改动」标签和 transcript 中。

成功标准：第 8 节的自动测试通过，实机验收清单逐项确认。

## 2. 已确认的决策

| # | 决策 |
| --- | --- |
| 1 | 不做会话树面板，也不做 Navigate、分支摘要、Compact 按钮等树面板功能。WebUI 代码不改。 |
| 2 | 消息上只做复制、Branch、Fork。Branch 的含义是「编辑并重新提问」：点击只进入编辑状态，发送时才切换分支。 |
| 3 | 消息到条目的对应关系用现有的 `Tree` 方法查，后端不为消息操作做改动。 |
| 4 | 离开的旧分支保留在后端，desktop 不显示，也不提供切回的入口。 |
| 5 | 「改动」标签：文件树在左，diff 在右。 |
| 6 | git 范围按 T3 的方式加载：先取文件清单，再按文件加载 diff；大小上限按单个文件计算，为 1 MiB。 |
| 7 | 按轮次快照存在工作区仓库的隐藏 ref 中，只在 Git 仓库中启用。 |
| 8 | 按轮次改动有两个入口：「改动」标签的范围选择，以及 transcript 中每轮最后一条回复下方的卡片。 |
| 9 | 「一轮」指一次运行（run）：从用户发出一条消息，到 agent 完成这次运行。 |

## 3. 消息操作

### 3.1 位置

| 行 | 操作 |
| --- | --- |
| 用户消息 | 复制、Branch |
| 助手回复 | 复制；已结束轮次的最后一条回复另有 Fork |
| slash 命令卡片、`!` 命令行、分支摘要、压缩、错误、邮件 | 无 |

- 操作按钮在鼠标悬停在这一行时显示，获得键盘焦点时也显示。用户消息的按钮放在气泡下方并右对齐，助手回复的放在正文下方并左对齐。
- 按钮是 ghost、xsmall 的图标按钮，带 tooltip 和无障碍标签：
  - 复制：`copy`；
  - Branch：`pencil`，tooltip「编辑并重新提问」；
  - Fork：`git-fork`，tooltip「Fork 为新会话」。
- 会话运行中（run state 不是 Idle）时，Branch 和 Fork 禁用，tooltip 说明原因。复制始终可用。
- 右侧面板里的子 agent 会话只显示复制。Branch 和 Fork 只出现在主卡片的顶层会话上。
- **已结束轮次的最后一条回复**：一条助手消息行，它之后、下一条用户消息之前，既没有别的助手消息行，也没有工具行；并且它不属于正在运行的轮次。轮次中间的回复后面还有工具结果，从那里 Fork，新会话会带着没有结果的工具调用。
- **用户消息行**（用来划分轮次，也用于第 6.2 节的序号）：Role 为 User，并且不是 slash 命令、`!` 命令或分支摘要。

### 3.2 复制

- 用户消息复制输入的原文。助手回复复制 Markdown 源文，不含思考内容。
- 使用 gpui-kit 的 `Clipboard` 组件，复制后图标短暂变成对勾。

### 3.3 Branch：编辑并重新提问

**进入编辑状态。** 点击 Branch 后：

1. 输入框进入「编辑消息」状态，记下被编辑消息的 message id。
2. 输入框原有的文字和图片先保存起来，然后换成这条消息的原文和图片。
3. 输入框上方显示提示条「正在编辑之前的消息」，右侧有「取消」按钮。
4. 输入框获得焦点。

这一步不调用后端。点「取消」或在输入框中按 Esc 会退出编辑状态，并还原输入框原有的内容。

编辑状态下点另一条消息的 Branch，会改为编辑那一条。还原时用的仍是第一次进入编辑前保存的内容。

**发送。** 在编辑状态下发送时：

1. 取一次 `Tree`。在 `entries` 中查找满足以下条件的条目：`kind == "message"`，`payload.message_id` 等于被编辑消息的 id，并且 `payload.content.type == "user"`。
2. 调用 `Branch`：`entryId` 是这个条目的 `parentId`（为空表示根），`summarize` 为 false。
3. 重新加载这个会话的 transcript，等 `session/resume` 返回后再继续。否则新消息的实时更新可能被重新加载清空。
4. 用普通发送流程提交输入框中的新消息。
5. 退出编辑状态，丢弃保存的原有内容。

会话运行中时，编辑状态下的发送按钮禁用。

**重新加载 transcript。** 分支切换后，已有的 projection 还是旧分支的内容。重新加载复用打开会话时的步骤：清空 projection、读取运行状态、通过 `session/resume` 回放整个 transcript。这一段从 `SessionRegistry::attach` 中提取成 `SessionHandle` 的方法，由 attach 和分支切换共用。会话视图只持有 handle 和客户端，拿不到 registry。

**出错。** 任何一步失败时，都用通知提示错误。输入框保留编辑后的内容，并保持在编辑状态，方便重试。找不到条目时，提示「找不到这条消息的记录」。

### 3.4 Fork

1. 取一次 `Tree`，找到 `payload.message_id` 等于这条回复 id 的 `message` 条目。
2. 调用 `Fork`，参数是这个条目的 id 和当前会话的 cwd。
3. 刷新会话列表，在新 Tab 中打开返回的会话并激活它。

失败时用通知提示，当前会话不受影响。Fork 进行中，按钮显示加载状态，防止重复点击。

## 4. 「改动」标签

### 4.1 布局

```text
┌ 相对 origin/main │ 未暂存 │ 轮次 ▾ ──────────── +a −d  [⊟] [↻] ┐
├──────────────┬────────────────────────────────────────────────┤
│ 文件     117 │ ▾ crates/acp/src/recovery.rs          +8 −6    │
│ ▾ crates     │   @@ -236,13 +236,15 @@ …                       │
│   ▾ acp/src  │   …                                            │
│     diff.rs  │ ▸ crates/acp/src/server.rs   （加载中）        │
│     …        │                                                │
└──────────────┴────────────────────────────────────────────────┘
```

- 文件树在左，diff 在右，中间可以拖动调整宽度。文件树默认宽 12rem。「隐藏文件树」按钮保留，隐藏后 diff 占满整个宽度。
- 文件树的行和现在一样：文件夹在前，只有一个子文件夹的文件夹链合并成一行；文件行显示着色的文件名、绿色的增加行数、红色的删除行数和状态字母。
- 范围选择从左到右依次是：
  - 「相对 origin/main」，按钮名是实际的基准名；
  - 「未暂存」；
  - 「轮次 ▾」下拉，见第 6.2 节。
- 不是 Git 仓库时，整个标签和现在一样不出现。

### 4.2 文件清单

新增扩展方法 `_clawcode/workspace/git_changes`：

- 参数：`root` 和 `scope`（`base` 或 `unstaged`）。
- 返回改动文件列表，以及合计的增删行数。每个文件包含路径、改名前的路径、状态、增加行数、删除行数和是否为二进制。
- `base` 范围：`git diff --raw --numstat -z -M <基准>`（raw 段给出状态，numstat 段给出行数），加上未跟踪的文件（`git ls-files --others --exclude-standard`）。基准的选取和现在相同：有上游时用 merge-base，否则用 `HEAD`。
- `unstaged` 范围：`git diff --raw --numstat -z -M`，加上未跟踪的文件。
- 文件数上限沿用 `WORKSPACE_CHANGE_LIMIT`。超过时标记截断，界面顶部提示「只显示前 5000 个文件」。

未跟踪文件的行数按文件行数计算。超过单文件上限（1 MiB）或为二进制的文件，不计行数，界面上也不显示行数。

### 4.3 按文件加载 diff

- `_clawcode/workspace/git_diff` 的 `path` 改为必填，一次只返回一个文件的 patch。`WORKSPACE_DIFF_LIMIT` 改为 1 MiB，含义改为「单个文件的 patch 上限」。
- 右侧按文件清单的顺序，为每个文件放一个折叠头（路径、增删行数）。还没加载的文件，内容区显示占位。
- **滚动加载**：可见区域及其后方 4 个文件中还没加载的，每次最多请求 4 个。上一批没有返回前，不发下一批。
- **点击文件树**：立即请求这个文件，并滚动到它的位置。
- 超过上限的文件只显示前面的部分，文件头下方注明「文件过大，无法完整显示；行数包含全部改动」；没有计行数的文件只注明「文件过大，无法完整显示」。二进制文件显示「二进制文件」。
- 刷新时（↻ 按钮，或文件系统变化触发的刷新）重新取文件清单。已加载的文件中，增删行数没变的保留，变了的重新加载。
- 删除现在的「差异过大，只显示前 2 MiB」提示。

## 5. 按轮次快照（后端）

### 5.1 何时拍快照

- 只对 Git 仓库中的顶层会话启用。子 agent 的运行不单独拍快照：它们的改动落在父会话这一轮的时间窗口里，会算进父会话的这一轮。
- **起点**：一次运行开始、发出第一次模型请求之前拍一次。最多等 5 秒；超时就放弃这一轮的快照，运行照常继续，这一轮不记录改动。
- **终点**：运行的执行部分结束后（成功、取消、失败都算）、发出运行结束事件之前拍一次，上限 10 秒。超时这一轮也不记录改动。放在运行结束事件之前，desktop 收到运行结束、刷新快照列表时，这一轮的快照已经写好了。

### 5.2 怎么拍

1. 把仓库真实的 index 复制成一个临时 index 文件，以便复用文件状态缓存。
2. 设置 `GIT_INDEX_FILE` 指向这个临时 index，执行 `git add -A`。这一步遵守 `.gitignore`。
3. 执行 `git write-tree` 和 `git commit-tree`，得到快照提交。
4. 用 `git update-ref` 写入 `refs/clawcode/checkpoints/<会话 id>/<运行 id>/start` 或 `/end`。
5. 删除临时 index。

用户的 index、HEAD、分支和工作区文件都不受影响。

- 终点快照的提交说明保存 JSON 元数据：运行 id，以及这一轮最后一条助手消息的 message id（简称 anchor）。
- anchor 的取法：从当前分支的叶子往根找，取遇到用户消息之前的第一条助手消息。如果先遇到用户消息（这一轮没有回复），anchor 为空，desktop 不显示这一轮。
- 同一个仓库的快照串行执行（按仓库加锁），避免多个会话同时写。

### 5.3 生命周期

- 删除会话时，删除 `refs/clawcode/checkpoints/<会话 id>/` 下的所有 ref。
- Fork 出来的新会话不复制快照，它从自己的第一轮开始记录。
- 快照按运行 id 存放。Branch 后离开的那些轮次，快照仍然有效，只是不再显示（见第 6 节）。
- 拍快照失败时只记录 warn 日志，不影响运行。

### 5.4 扩展方法

**`_clawcode/session/checkpoints`**

- 参数：`root`（会话的 cwd，由 desktop 传入，和 workspace 方法一样）和 `sessionId`。
- 返回起点和终点都存在、并且两者 tree 不同的运行列表，按开始时间排列。
- 每项包含：
  - 运行 id；
  - anchor message id；
  - 改动文件列表和合计增删行数（`git diff --numstat -z <start> <end>`，文件字段和第 4.2 节相同）。

**`_clawcode/session/checkpoint_diff`**

- 参数：`root`、`sessionId`、`runId` 和 `path`。
- 返回 `<start>` 到 `<end>` 之间这个文件的 patch，上限为 1 MiB，返回格式与 `git_diff` 相同。

会话不在 Git 仓库中时，`checkpoints` 返回空列表。

### 5.5 已知局限

运行期间，同一个工作区里其他会话的修改，以及用户手动做的修改，都会算进这一轮。T3 Code 也有这个局限。

## 6. 按轮次改动（desktop）

### 6.1 transcript 中的卡片

- 打开会话时取一次 `_clawcode/checkpoints`；每次运行结束后再取一次。
- 只显示 anchor message 在当前 transcript 中的轮次，这样离开的分支上的轮次自然不显示。
- 卡片放在 anchor 回复的操作按钮下方：
  - 折叠时显示一行：「改动了 N 个文件」、绿色的 `+a`、红色的 `−d`、一个展开箭头；
  - 展开后显示与「改动」标签相同样式的文件树。
- 点卡片的标题行：打开右侧面板的「改动」标签，并选中这一轮。
- 点卡片中的文件：同上，并加载、定位到这个文件。
- anchor 回复没有自己的行时（只有思考、被折叠进运行摘要，或只有工具调用，常见于被取消的运行），卡片单独成一行，放在这一轮的末尾、用量行之前。
- 没有改动的轮次不显示卡片。

### 6.2 「改动」标签的轮次范围

- 「轮次 ▾」下拉列出 6.1 节中可显示的轮次，最新的在前：
  - 第一项是「最近一轮」；
  - 其余为「第 N 轮 · 用户消息首行」。N 是这一轮在当前 transcript 中的序号；首行过长时截断，显示省略号。
- 选中某一轮后，文件清单来自 `checkpoints` 中这一轮的文件，diff 按文件通过 `checkpoint_diff` 加载。加载方式和第 4.3 节相同。
- 没有可显示的轮次时，下拉禁用，tooltip 说明「还没有记录到改动的轮次」。
- 选中的范围按会话保存在面板状态中；切换会话时，各自保留自己的选择。
- Branch 之后，选中的轮次如果不在新分支上，「改动」标签回到「相对基准」。重放 transcript 期间不做这个判断。

## 7. 代码组织

| 位置 | 内容 |
| --- | --- |
| `protocol` | `git_changes`、`checkpoints`、`checkpoint_diff` 的参数和返回类型；`WORKSPACE_DIFF_LIMIT` 的新含义 |
| `kernel` | 定义 `RunCheckpoints` 接口；在运行前后、删除会话时调用它。不包含 git 操作 |
| `acp/src/workspace/checkpoint.rs` | 快照的拍摄、列出、单文件 diff 和删除，按仓库加锁；由 app 注入 kernel |

| `desktop/src/ui/composer` | 编辑状态、提示条、暂存与还原 |
| `desktop/src/session.rs` | 从 attach 中提取到 `SessionHandle` 的重新加载；快照列表 |
| `desktop/src/ui/panel/changes.rs` | 新布局、文件清单、按文件懒加载、轮次范围 |

## 8. 测试与验收

### 8.1 自动测试

**后端**（在临时 Git 仓库中）：

- 快照：
  - 包含未跟踪的文件，排除被忽略的文件；
  - 拍快照前后，用户的 index、HEAD 和分支不变；
  - 起点到终点的文件列表和增删行数正确；tree 相同的运行不出现在列表中；
  - 删除会话后，它的 ref 全部删除；
  - 非 Git 目录不拍快照，`checkpoints` 返回空列表；
  - 取消和失败的运行也拍终点，起点超时的运行不拍终点，子 agent 不拍。
- `git_changes`：
  - `base` 范围包含已提交但未推送的改动和未跟踪的文件；
  - `unstaged` 范围只含工作区相对 index 的改动；
  - 超过文件数上限时标记截断。
- `git_diff` 和 `checkpoint_diff`：
  - 单个文件的 patch 正确；
  - 超过 1 MiB 时截断并标记；
  - 缺少 `path` 时返回参数错误。

**desktop 纯逻辑：**

- 按 message id 在 `SessionTreeSnapshot` 中查找条目：
  - 找到用户消息时返回它的父条目，包括父条目为根的情况；
  - id 不存在时返回空；
  - 只匹配 `message` 类型的条目。
- 「已结束轮次的最后一条回复」的判断：
  - 轮次中间的回复不算；
  - 运行中的最后一轮不算；
  - 空闲时最后一条回复算；
  - 被用户消息隔开的每一轮，各自的最后一条都算；
  - 以工具行结束的轮次（例如运行被取消）没有 Fork 点。
- 懒加载批次：根据可见范围和已加载、加载中的集合，算出下一批最多 4 个文件；上一批还在加载时，不产生新的一批。
- 轮次过滤：anchor 不在 transcript 中的轮次被排除；序号按 transcript 中的顺序计算。

按规则 7，UI 部分不写测试。

### 8.2 实机验收

使用真实的 provider 和隔离的 XDG 目录：

- **消息操作：**
  - 复制用户消息和助手回复，粘贴后确认是原文。
  - 在第二轮的用户消息上点 Branch，输入框填入原文，提示条出现；点「取消」后，输入框还原。
  - 再次进入编辑，修改后发送：transcript 只剩第一轮和新的提问，回复正常生成；重启应用后仍然显示新分支。
  - 在第一轮的最后一条回复上点 Fork：新 Tab 打开，内容是第一轮；原会话不变。
  - 运行中时，Branch 和 Fork 禁用；轮次中间的回复上没有 Fork。
- **「改动」标签：**
  - 在本仓库（本地有未推送的提交）中，「相对 origin/main」列出全部改动文件，没有「差异过大」提示；向下滚动时 diff 逐批加载；点击文件树中靠后的文件，可以直接跳过去。
  - 文件树在左，可以拖动调整宽度，可以隐藏。
- **按轮次改动：**
  - 让 agent 在一轮中修改两个文件并新建一个文件：这一轮最后一条回复下出现卡片，文件和行数正确；点卡片中的文件，「改动」标签切到这一轮并定位到该文件。
  - 没有改动的一轮不出现卡片。
  - 「轮次 ▾」中「最近一轮」和「第 N 轮」的内容正确。
  - 用 `git status`、`git log` 确认用户的 index 和 HEAD 没有变化。

## 9. 不做的内容

- 会话树面板、Navigate、分支摘要、Compact 按钮。
- 切回旧分支。
- 从用户消息或轮次中间 Fork；编辑助手回复。
- 用快照回滚工作区。
- 非 Git 目录的按轮次改动。
- diff 的并排视图、自动换行、忽略空白等显示选项。
