# Desktop Provider 登录与设置分页（M4c）设计

日期：2026-11-24。状态：待确认（见第 2 节标「待确认」的条目）。

本文是 M4 的第三个子项目。后端的登录流程沿用 [ACP 登录设计](./2026-11-05-acp-provider-login-design.md)，设置对话框沿用 [M3b 外壳重构设计](./2026-11-21-desktop-shell-redesign-design.md)第 7 节。没有被本文提到的部分仍然有效。

## 1. 背景与目标

后端和 WebUI 已经支持设备码登录，desktop 没有入口：

- `backend/client.rs` 没有保留 `initialize` 返回的 `authMethods`，也没有发送 `auth/login` 的方法。
- `auth/login` 期间后端发来的 elicitation 属于 `requestId` 范围，desktop 一律回复 `cancel`，登录因此被取消。
- 切换到未登录的模型时，只提示「需要先登录该模型的 Provider」。
- 发消息被 `auth_required` 拦下时，只提示发送失败，没有引导。
- 草稿里选了未登录的模型，创建会话时切换失败只记日志，会话仍用原来的模型发出消息，用户不知道。

设置对话框也还缺工作区、Provider、关于三个分页。

成功标准：只用 desktop，就能从没有凭据的状态完成登录并继续对话；第 8 节的验收逐项通过。

## 3. 连接层

### 3.1 登录方法

`AcpClient::connect` 保留 `initialize` 返回的 `AuthMethod::Agent` 列表，提供 `login_methods()`。没有可登录的 provider 时为空。

### 3.2 `auth/login`

- 新增 `AcpClient::login(method_id)`：发送 `auth/login`，不设超时，用户可能要几分钟。
- 返回值沿用 `BackendError`：用户取消（-32800）为 `Cancelled`，其他失败为 `Request`。

### 3.3 `requestId` 范围的 elicitation

- 只有 URL 模式，并且 `_meta` 的 `ProductIdentity::ACP_NAMESPACE` 下有 `userCode` 的，才作为登录请求接收。
- 其他 `requestId` 范围的 elicitation 仍然回复 `cancel`。
- 登录请求没有会话，不能走 `SessionRegistry` 的会话路由，它现在会拒绝没有会话的请求。新增 `BackendEvent::SignIn`，带请求 id、验证地址、code 和 provider 名，由外壳处理。
- 撤销沿用 `RequestCancelled`。外壳和会话都收到，各自只处理自己的请求 id。

### 3.4 `_clawcode/auth/status`

- 参数为空，返回每个登录方法的 `methodId` 和状态：
  - `signedIn`：凭据可用；
  - `signInRequired`：需要登录；
  - `unknown`：网络不通、刷新接口出错、检查超时或凭据文件损坏，无法判断。
- `ProviderAuth::check` 现在把「无法判断」当成通过。把判断部分提取成返回三态的方法，`check` 在它之上把 `unknown` 转成通过，行为不变。
- Kernel 的 `Model` trait 增加同名方法，Kernel 只转发。ACP 把它作为独立任务运行，最长 10 秒，不阻塞其他请求。
- 日志只写 provider id 和状态，不写凭据。

## 4. 登录流程（desktop）

### 4.1 归属

`HostState` 持有 `SignIns`：按方法 id 记录进行中的登录。同一个方法再次发起时，等待已有的那一次，不再申请 code。按连接隔离，符合原设计 4.6。

任何入口只调用 `AppView::sign_in(method_id)`，得到「成功 / 取消 / 失败」三种结果。

### 4.2 入口

| 入口 | 登录成功后 | 取消 | 失败 |
| --- | --- | --- | --- |
| 会话中切换模型 | 自动重试一次切换；再次被拦则提示切换失败 | 留在原模型，不提示 | 留在原模型，提示「登录未完成，请重试」 |
| 会话中发消息 | 输入已还回，用户手动再发 | 不提示 | 提示「登录未完成，请重试」 |
| 草稿发送 | 继续创建会话、应用选择并发送 | 输入还回草稿 | 输入还回草稿，提示「登录未完成，请重试」 |
| 设置 › Provider | 刷新状态 | 不提示 | 提示「登录未完成，请重试」 |

- 切换模型期间，模型选择保持禁用并显示原模型（现有的 `config_busy`）。
- 会话的 `send_keeping` 收到 `AuthRequired` 时，先还回输入，再发起登录，不显示「发送失败」。
- 草稿的 `create_session` 应用选择时收到 `AuthRequired`：会话已经创建但没有消息。登录成功后在同一个会话上重试；取消或失败时删除这个空会话，草稿保持原样。选择失败的其他原因不再静默，提示切换失败，并同样还回输入。

### 4.3 登录对话框

```text
┌ 登录 ChatGPT ────────────────────────┐
│ 打开验证页面，输入下面的代码：       │
│                                      │
│        ABCD-EFGH   [复制]            │
│                                      │
│ ⟳ 等待授权…                          │
│              [取消]  [打开验证页面]  │
└──────────────────────────────────────┘
```

- 用 gpui-kit `Dialog`。code 用等宽字体，可以选中；复制用 `Clipboard`。
- 「打开验证页面」用系统浏览器打开，不回复 elicitation，对话框保持显示。
- 只接受 `https` 的验证地址，其他协议不打开，对话框只显示地址文本。
- 打开时焦点在「取消」上。Esc、点「取消」和关闭按钮都回复 `cancel`，点对话框外不关闭。
- 后端撤销请求时，对话框自动关闭，焦点还给打开前的元素；那个元素已经不在时还给外壳。
- 从设置里发起时，登录对话框叠在设置对话框之上，关闭后回到设置。
- 同时有两个方法在登录时，按到达顺序依次叠加，Esc 只关最上面一个。
- 申请 code 期间（最长 30 秒）还没有对话框。发起的按钮显示加载状态；用户可以从按钮旁的「取消」放弃，desktop 通过取消 `auth/login` 请求实现。
- 连接断开时关闭对话框，按失败处理。

## 5. 设置分页

分页顺序：通用、外观、字体、工作区、Provider、关于。

### 5.1 工作区

- 每个工作区一行：名称、路径（过长时中间截断，悬停显示全路径）、当前分支，或「找不到文件夹」。
- 行尾的图标按钮：上移、下移、在文件管理器中打开、移除。第一行的上移、最后一行的下移、找不到文件夹时的打开都禁用。图标按钮都带 tooltip 和无障碍标签。
- 列表下方「添加工作区…」，与 Ctrl+O 相同。
- 没有工作区时，显示一句说明和「添加工作区…」。
- 全部复用侧栏已有的 `move_workspace`、`remove_workspace`、`reveal_workspace`、`on_add_workspace`，不新增数据。移除和侧栏一样不需要确认：会话不会被删除，重新添加即可恢复。

### 5.2 Provider

- 每个登录方法一行：名称、状态和一个按钮：
  - 检查中：加载图标，按钮禁用；
  - 已登录：显示「已登录」，按钮「重新登录」；
  - 需要登录：警告色图标加「未登录」，主按钮「登录」；
  - 无法判断：显示「无法确认登录状态」，按钮「重试」，另有「登录」。
- 状态在打开分页时读取，登录结束后再读一次。不轮询。
- 后端未连接时，显示「后端未运行」。
- 列表下方说明：API key 在配置文件中设置，并显示配置文件路径和「在文件管理器中打开」。
- 没有登录方法时，只显示这段说明。

### 5.3 关于

- 版本、配置文件路径、数据目录。路径行有「复制」和「在文件管理器中打开」。
- 配置文件路径用已有的 `config_location()`；数据目录用 `AppConfig::data_root()`。
- 配置加载失败时，数据目录显示「配置未加载」。

## 6. 错误处理

| 情况 | 结果 |
| --- | --- |
| 用户取消 | 不提示 |
| 申请 code 超时、轮询失败、15 分钟未完成 | 「登录未完成，请重试」 |
| 后端在登录中断开 | 对话框关闭，提示后端已停止（现有提示） |
| 状态读取失败 | 该行按「无法判断」显示 |
| 打不开浏览器 | 对话框保持，用户可以复制地址 |

code 和验证地址不写入日志。

## 8. 测试与验收

### 8.1 自动测试

- **provider**：有效凭据为 `signedIn`；没有凭据、`invalidated` 为 `signInRequired`；刷新 5xx 和超时为 `unknown`；`check` 的已有测试不变。
- **acp**：`_clawcode/auth/status` 返回每个方法一次；没有登录方法时为空；检查期间连接仍能处理其他请求。
- **desktop 连接**（脚本化后端加一个可登录的假模型）：
  - `login_methods` 来自 `initialize`；
  - 登录请求产生 `BackendEvent::SignIn`，code 和地址正确；回复 `cancel` 后 `login` 返回 `Cancelled`；
  - 没有 `userCode` 的 `requestId` 范围 elicitation 仍被取消。
- **`SignIns`**：同一方法只发一次请求；结果通知所有等待者；结束后可以再次登录。
- **草稿**：选择被拦后取消，不发出消息，空会话被删除，输入还回；登录成功后在同一会话发送。
- 按规则 7，对话框和设置分页的界面不要求测试。

### 8.2 实机验收

隔离的 XDG 目录，空的 `auth_dir`，生产后端：

- 会话中切换到 ChatGPT 模型：对话框显示 code；复制正确；「打开验证页面」后对话框仍在；点「取消」，模型不变，选择恢复可用。
- Esc 取消后焦点回到发起处。
- 未登录时发消息：输入还回，对话框出现。
- 草稿选 ChatGPT 模型后发送并取消：输入还回，侧栏没有多出空会话。
- 设置 › Provider：状态正确；从设置发起登录，取消后回到设置。
- 设置 › 工作区：添加、上移、下移、移除、打开；重启后顺序保持。
- 设置 › 关于：版本和路径正确。
- 浅色和深色、中文和英文、960×640 各看一遍。
- **需要用户配合**：用真实账号完成一次登录，切换自动完成，消息有回复。

## 9. 不做的内容

- 登出、浏览器回调登录、在界面里编辑 API key 或 provider。
- MCP OAuth（属于后面的 Skills 和 MCP 子项目）。
- 模型列表中的「未登录」标记。
- 直接命令（例如 `/compact`）和子智能体未登录时弹出登录，仍只显示错误。
- 右侧面板的计划、待办、后台终端标签，以及会话关系的补充。
