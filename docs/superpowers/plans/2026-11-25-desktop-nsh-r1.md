# 桌面 R1 实施计划：可信设备远程控制

**目标**是在两个独立的桌面实例之间完成配对，由遥控器在主机上对话和审批文件修改，再从主机撤销设备。

**架构**沿用一个主机一个 `HostStore`。Rust 的 `remote` crate 持有设备身份、信任记录和 iroh 连接。桌面扩展把已授权的连接送到本机后端使用的同一个 ACP 服务。前端沿用原有会话和审批界面。

**技术栈**为 NSH 0.7.1、Rust、Tokio、iroh 1.5 和 ACP v2。逐项实施并用实际结果核对清单。设计及探针结果见[桌面客户端设计](../specs/2026-11-25-desktop-nsh-design.md)和[可行性记录](../../../apps/desktop/FEASIBILITY.md)。

## 约束与验收重点

- Linux 使用 Wayland。同机两实例使用独立的绝对 `XDG_DATA_HOME`，已有桌面设置仍从 NSH 的应用目录读取。测试时分别指定后端数据目录，以便两实例能同时获得数据库租约。
- 设备私钥只由原生端使用。配对码至少含 128 位随机密钥，有效期 5 分钟。主机上的人必须明确同意；错误、过期、重复使用或主机拒绝时均不能建立 ACP 连接。
- 撤销信任必须立即关闭该设备的现有连接，且重启后仍然有效。临时断开连接保留信任，允许用户重连。
- 本机后端启动失败仍能操作远程主机。远程连接不能办理主机的 Provider 登录或凭据管理。日志不记录配对码、私钥和远程帧正文。
- 直接连接测试使用本机端点。另行记录 relay 和两台物理设备的实测条件，避免把同机结果计作跨 NAT 验收。

## 1. 实例目录、设备身份与配对

- [x] 在 `crates/remote` 为设备密钥、主机信任记录和遥控器的主机记录确定持久化格式。先测分目录产生不同身份、同目录重启保留身份、进程内并发共享同一身份、第二个进程不能同时占用该目录、无效密钥报错，以及 Unix 文件权限。
- [x] 以 `clawcode/acp/1` 建立 iroh 双向流。把邀请绑定到主机身份、时效和一次显式批准。用本机两个端点验证正确配对、错误次数耗尽、过期、拒绝、重放、重连及撤销。
- [x] 接入局域网发现、开发用 relay 与可配置的 relay 地址。主机只有在用户开启远程控制后才接收连接。每条线上连接关联实际通过 TLS 认证的公钥。

## 2. ACP 权限和原生桥接

- [x] 在 `crates/acp/src/transport.rs` 增加 `serve_remote_lines`。在 `server.rs` 的初始化、登录和扩展分发入口应用传输权限。用配置了登录方法的真实 ACP 服务证明远程能列出会话，但不会得到登录方法或调用凭据接口。
- [x] 在 `apps/desktop/ext/backend` 接入主机共享的 ACP 服务，并提供原生配对事件、批准、撤销和帧收发。遥控器连接的生命周期独立于本机后端。验证主机关停、拒绝授权及连接结束时释放在途资源。

## 3. 桌面配对和会话

- [x] 在设置中增加远程控制开关、设备名、邀请与二维码、待确认请求和已信任设备。提供复制、拒绝、断开和撤销操作，提供简体中文和英文文案。
- [x] 将已配对主机恢复到 `AppStore`。通过 `RelayTransport` 复用会话、流式回复和审批卡。离线后提供重试。工作区路径属于选中的主机。
- [x] 在主机切换器与设置检查键盘操作、可访问名称、二维码可读性、亮暗外观和连接状态。涉及远程主机断开时，正在查看的本机会话仍可用。

## 4. 验收

- [x] 运行 Rust 工作区测试、Clippy、格式检查，以及桌面 `nsh check`、`nsh build` 和 `nsh test`。
- [x] 在同一个 Wayland 会话打开两个实例，分别更改设置，验证设置和设备身份独立。主机显示配对请求，明确允许后，遥控器可以建立会话。
- [x] 使用配置好的真实 Provider，从遥控器请求内置 `write` 写入主机工作区外的临时文件。第一次拒绝后核验文件未变，再发起独立请求，批准后核验主机文件的实际内容。
- [x] 主机撤销，遥控器收到断线状态。用原记录重连应失败，主机自身继续工作。记录截图、命令结果及未能实测的环境。

## 2026-11-26 验收记录

- 两个 GTK 窗口运行在同一个 Wayland 会话，各自使用单独的桌面目录和后端数据库。两份设备私钥不同，权限均为 `0600`。主机切换到中文深色后，控制端仍为英文。旧版设置的语言与外观继续保存在 NSH Storage，共享默认为关闭。
- 从主机窗口截图解码二维码，内容与复制按钮给出的配对码逐字一致。主机点「允许」后，控制端可以选择主机上的工作区并发起对话。
- 使用主机配置的真实模型，在控制端发起两次独立的工作区外 `write` 请求。第一次拒绝后目标文件不存在。第二次允许后在主机文件系统读到了 `R1-APPROVED`。
- 将控制端的本机后端配置指向不存在的文件后重启，已配对主机仍能重新连接。主机撤销后在线数降至零，控制端进入离线状态，点击重试收到拒绝。主机仍可使用设置和新会话。随后关闭共享并正常关闭两个窗口，两个进程均以状态码 0 退出，日志中未出现 iroh 端点未关闭的警告。
- 公共 relay 使用临时设备身份和合成帧单独验证。控制端禁用全部 IP 直连传输后，仍能配对并完整收回带有中文的帧。单次 QUIC 握手为 2.306 秒，单帧往返为 1.781 秒。两端在同一台电脑上，两台物理设备之间的跨 NAT 实测仍待具备设备条件。
- Rust 工作区共有 1461 项通过、2 项按项目标记忽略。桌面 NSH 套件 84 项通过。`nsh check`、`nsh build`、工作区严格 Clippy、格式检查以及仓库 pre-commit 钩子均通过。

双实例运行方式和操作步骤见[桌面 README](../../../apps/desktop/README.md)。

## 代码审查修复验收

- 通过真实 ACP 连接分别发送成功和失败的请求。打开 SDK 的 TRACE 和应用的 DEBUG 后，测试能找到方法名和失败状态，并检查请求正文、响应正文及错误附带的数据是否出现在日志中。该测试在修改前失败，修改后通过。
- 启动共享的偏好由原生设备配置保存。已有设备配置缺少这项偏好时，用户需重新开启共享。关闭开关时，桌面先同步写入偏好，再等待监听器释放连接。
- 在 Wayland 上正常关闭并重启主机两次，分别验证开启共享后能恢复监听，关闭共享后保持关闭。控制端在主机批准前关闭配对框，主机的待批准请求随即消失；生成新码后，两端立即完成了新的配对。
- 使用已配置的真实模型在两个窗口间重测文件审批。拒绝后主机文件不存在，单独发起的新请求获准后文件内容为 `R1-APPROVED`。控制端在本机后端启动失败时仍可重连。随后主机撤销设备，控制端离线，再次重试收到拒绝。
- 将控制端发送队列填满后，下一帧发送失败会关闭整条连接，等待审批的两端均能结束等待。桌面测试覆盖重连期间与重连失败后保留的会话列表、正文和草稿，也覆盖通过前进、后退重新打开远程会话。
- 原生测试覆盖同意与超时、撤销竞争，确认未完成时不留下新授权。Linux 上配置使用原子替换并同步父目录。撤销遇到写盘错误时，本次进程立即拒绝该设备；重试成功后再重新打开配置，设备依然被拒绝。
- 修复后 Rust 工作区 1469 项通过，2 项按项目标记忽略。桌面 NSH 套件 94 项全部通过。严格 Clippy、格式检查、仓库 pre-commit 钩子、`nsh check` 和 `nsh build` 均通过。本轮桌面验收使用同机的两个独立 Wayland 实例，未覆盖两台物理设备之间的跨 NAT 连接。

## 第二轮代码审查修复验收

- 已有记录的会话重新打开时，回放期间到达的运行状态立即更新，原有历史保持可读。成功响应后一次替换正文，断线时丢弃未完成的回放。定向测试同时检查运行状态与会话目录的对象标识。
- 在同机的 NSH headless 引擎上，对同一份已有记录连续回放 2000 个独立消息帧。修复前每次回放中途替换会话目录 2000 次，修复后为 0 次。交替运行 5 轮的耗时中位数分别为 422 毫秒和 81 毫秒。该测量覆盖桌面状态处理，不包含网络传输和绘制。
- 配对与撤销按设备身份协调。一台设备的配对写盘被阻塞时，撤销另一台在线设备仍能立即断开其连接。即使发起撤销的界面提前关闭，主机也会完成已开始的撤销。
- 地址簿仅在名称或连接地址等记录发生变化时写盘。在 Wayland 控制端重新启动并重连后，已知主机记录的内容和 inode 均保持不变。
- 远程 ACP 桥每次只交付一个等待 JavaScript 确认的批次，通常最多 8 帧、64 KiB，超出该大小的单帧独立交付。通过真实 QuickJS 和回环 QUIC 验证回调挂起后按序恢复、挂起期间主机撤销和回调抛错时断开连接。桌面原生接口和集成测试统一使用 `beginPairing`、`dial`、`accept`。
- 仅访问本机设备设置时，两个 Wayland 实例的专用网络线程数均为 0。首次开启共享或主动拨号时才启动两个 Tokio 异步工作线程，阻塞任务可按需使用额外线程。
- 本机服务结束后，运行时最多等待 5 秒清退线程。原生测试使用一个阻塞任务验证超时会传给所有关闭等待方。阻塞任务可在释放后自行结束。
- 同机两个独立 Wayland 窗口使用真实模型重测远程文件审批。拒绝后主机目标文件不存在，再次请求并批准后写入预期内容。随后撤销控制端，原设备重连收到拒绝。
- Rust 工作区 1476 项通过，2 项按项目标记忽略。桌面 NSH 套件 100 项全部通过。严格 Clippy、格式检查、仓库 pre-commit 钩子、`nsh check` 和 `nsh build` 均通过。
