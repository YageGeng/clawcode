# Desktop M4c（Provider 登录与设置分页）实施计划

**Goal:** 在 desktop 里完成 provider 设备码登录，并补齐设置的工作区、Provider、关于分页。

**Spec:** [Desktop M4c 设计](../specs/2026-11-24-desktop-m4c-design.md)

**Architecture:**
- provider 把登录检查改成三态；kernel 转发；acp 暴露 `_clawcode/auth/status`。
- desktop 的 `AcpClient` 保留登录方法，管理进行中的登录；登录请求以 `BackendEvent::SignIn` 送到外壳。
- 外壳用一个对话框显示登录；四个入口只调用 `AcpClient::sign_in`。

## Global Constraints

- AGENTS.md 全部规则；新函数都有英文注释；超过 3 个字段的结构体用 `typed-builder`。
- 后端和连接层按 TDD；界面（规则 7）不要求测试，草稿流程有测试。
- code 和验证地址不进日志；带 code 的类型的 `Debug` 必须脱敏。
- 界面文案中英文都写进 `locales/app.yml`。
- 不提交，除非用户要求。

## Task 1：登录状态（protocol、provider、kernel、acp）

- [x] protocol：`SignInStatus { SignedIn, SignInRequired, Unknown }`、`ProviderSignIn { method_id, status }`（camelCase）、`AcpExtensionMethod::AuthStatus`（`_clawcode/auth/status`，query）。
- [x] provider 测试：有效凭据 `SignedIn`；无凭据与 `invalidated` 为 `SignInRequired`；刷新 5xx、超时、目录不可用为 `Unknown`；无 `auth` 的 provider 为 `SignedIn`。
- [x] provider 实现：`ProviderAuth::status`；`check` 改为调用它，行为不变；`ConfiguredModel::sign_in_status`。
- [x] kernel：`Model::sign_in_status`（默认由 `ensure_signed_in` 推出）、`ModelCatalog::sign_in_statuses`（按方法去重、并发）、`Kernel::sign_in_statuses`。测试：去重；默认实现的三种结果。
- [x] acp：处理 `AuthStatus`，用 `connection.spawn` 运行，不阻塞分发。测试：每个方法一次；无方法为空；检查卡住时连接仍能应答其他请求。
