# N2 桌面对话控件实施计划

依据[桌面设计规格](../specs/2026-11-25-desktop-nsh-design.md)和[R1 验收记录](./2026-11-25-desktop-nsh-r1.md)。使用现有 NSH 0.7.1 组件与 ACP v2，通过同一套桌面代码操作本机和已配对主机。Linux 使用 Wayland。

## 第一阶段：会话配置

1. 在桌面 ACP 客户端读取 `session/new`、`session/resume`、`config_option_update` 与 `session/set_config_option` 返回的选择项。每个主机独立维护各会话的已确认值，按接收顺序应用更新。一个会话有修改在途时避免重复提交，失败后保留已确认值。
2. 在输入框提供模型、思考等级与普通／计划模式的入口。选项来自当前会话，错误可见，离线状态可读。复用应用的弹层、字阶与动效，验证中英文、键盘、窄窗口及亮暗外观。
3. 在空白会话显式打开配置时，在所选主机和工作区创建会话，保留输入草稿。首次发送复用同一个会话。切换工作区或主机时隔离准备好的会话。
4. 通过 ACP 测试覆盖新建、恢复、选项广播、失败及断线。用同机两个 Wayland 实例分别修改本机与远程会话，检查切换主机、断开重连和会话重开后的值。

## 第二阶段：交互、命令与附件

1. 通过 ACP 的 `file_approval` 选项控制内置 `write` 和 `edit` 对工作区外文件的修改。默认沿用主机策略。逐次询问与自动同意只作用于当前会话，由主机持久化。计划执行由独立的审批请求决定。
2. 从主机的提问和回复记录还原待答问题，支持单选、多选、自由文本、逐题跳过和全部跳过。检查另一客户端已提交的排队回复，避免重复作答。侧栏标记等待回答或审批的会话。
3. 在审批卡展示主机提交的 Markdown 计划，提供「继续规划」和「批准并执行」。已批准的计划和待办进度可在输入框上方展开查看。
4. 输入以 `/` 开头的命令名时，从当前主机公布的会话命令中过滤建议。支持鼠标、上下键、Tab、Enter 和 Escape。补全后保留参数编辑机会。
5. 通过操作端的原生文件选择器添加图片。支持 PNG、JPEG、GIF 和 WebP。每条消息最多 5 张，单张上限 10 MiB，合计上限 20 MiB，与主机 ACP 输入限制一致。图片可以单独发送，或与文字一起发送。失败时完整恢复草稿。

## 2026-11-26 验收记录

| 场景 | 同机 Wayland 双实例验收结果 |
| --- | --- |
| 配置和恢复 | 在本机与已配对主机分别修改模型、思考等级和会话模式。首次发送使用配置时创建的会话并保留原草稿。断开后可阅读缓存，重连后同步主机的新值，重启后两个会话各自恢复。 |
| 工作区外写入 | 在远程会话选择逐次询问并拒绝，主机目标文件未创建。选择自动同意后再次调用内置写入，实际文件内容为 `N2-CURRENT-SESSION`。主机进程重启后恢复该会话的选择。ACP 回归另覆盖主机默认免询问、当前会话显式要求询问的情况。 |
| 提问和计划 | 控制端回答真实模型提出的问题，模型在原会话收到答案。自动同意外部写入的会话在执行计划前仍展示审批卡，批准后可以展开计划。另用本机会话批量跳过两个问题，选择继续规划，重开后核对两个跳过记录和计划被拒绝的结果。 |
| 斜杠命令 | 在本机与远程会话分别补全并执行 `/name` 和 `/session`，核对各自主机保存的标题及返回的会话信息。 |
| 图片 | 在本机和控制端分别用 GTK 文件选择器选取绿色圆形 PNG，配置的视觉模型均正确返回颜色。远程主机重开会话后仍显示图片数量，其会话历史中的图片与原始字节一致。 |
| 原生布局 | 检查英文亮色和简体中文深色。800 × 560 下三种文件审批策略的说明及选中标记均可读，模型弹层显示完整名称与思考等级。 |

### 审查修复后的回归

- 用截图中已有会话的副本在同机 Wayland 控制端重放。21 条助手消息中有 20 条含思考内容，只有最后一条有正文。展开后核对了全部 20 段思考、工具分组和最终答复。折叠后仍可阅读答复。
- 在另一条会话中重放 4 张各 7,080,032 字节的 PNG。生产 ACP 逐字节还原了四张图片，最大一帧为 9,441,136 字节。已配对的控制端显示四条图片消息，并可通过同一连接继续打开其他会话。
- 自动回归覆盖连续新建草稿、在途请求与授权隔离、切换工作区后保留斜杠草稿并更新命令、离线查看审批模式、跳过与另一端回答同时发生，以及切换分支后刷新问题和计划。
- 新写入的会话审批设置使用 v4 已有的自定义条目。当前版本也能恢复 N2 预览记录，按会话和顺序处理两种格式。早于 N2 的主机仍无法读取已含预览专用记录的旧文件。
- Rust 工作区 1481 项通过，2 项按仓库标记忽略。桌面 NSH 130 项通过。Clippy、TypeScript、格式、pre-commit 钩子、`nsh check` 和 `nsh build` 均通过。

### 第二轮审查后的回归

- 默认询问的主机在会话选择自动同意后仍保护硬链接指向的备份。批次执行期间切换会话策略，后续进入文件修改步骤的调用会读取新策略。
- 首次发送等待创建时继续输入或切换工作区，原消息送往原会话，编辑器保留当前草稿。主机已确认创建后，即使目录刷新或挂接失败，重试也复用同一个会话。另验证了超量选图时整批提示，以及待办更新后保留计划折叠状态。
- 切换分支后若历史刷新失败，桌面自动重试一次。待答问题随历史和主机的占用快照一起发布。主机撤回尚未写入的答案或跳过操作后，问题重新开放。
- 在含 1,000 个回合的会话追加一段已可见的思考内容，回合分组的消息查找次数由 5,997 降到 0。追加一个用户回合只查找 7 次。另对 3,000 个混合更新帧作增量与全量分组对照。
- 同机两个生产 Wayland 窗口完成配对，控制端回放了四张各 7,080,032 字节的 PNG 及截图中的历史会话。展开后显示全部 20 段思考、工具分组和最终答复，折叠后答复仍可见。
- Rust 工作区 1,487 项通过，2 项 MCP 互操作测试按仓库标记忽略。桌面 NSH 142 项全部通过。严格 Clippy、TypeScript、格式、仓库 pre-commit 钩子、`nsh check` 和 `nsh build` 均通过。

### 会话输出默认折叠

- 最终回复直接显示正文，流式输出时同步可见。思考、中间助手消息、工具详情、文件改动和计划正文默认收起。展开工作记录即可按事件顺序看到每次工具调用的名称。再次收起和打开工作记录会恢复其中各项的展开选择。
- 用截图中的历史会话在两个同机 Wayland 窗口间回放，核对了 34 次 `exec_command`、4 次 `write_stdin` 和 20 段思考。另用含 `read`、`grep`、`edit`、MCP 工具和 `todo_write` 的验收会话核对了工具名称、输入、结果和文件补丁，并检查了亮色和深色窗口。
- 桌面在 ACP 初始化时声明 `_meta.clawcode.toolCallHistory=true`。支持该选项的主机同时发送 `todo_write` 调用记录和计划进度。旧版主机仍只提供计划进度。
- 桌面 NSH 146 项通过。Rust 工作区 1,488 项通过，2 项 MCP 互操作测试按仓库标记忽略。
