# Desktop M4b（消息操作、改动标签、按轮次改动）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** transcript 消息上的复制、Branch、Fork；「改动」标签文件树在左、按文件懒加载；每次运行前后给 Git 工作区拍快照，按轮次查看改动。

**Architecture:**
- protocol 定义新的扩展方法和类型。
- kernel 只定义 `RunCheckpoints` trait，在运行前后和删除会话时调用它，不碰 git。
- acp 的 `workspace` 模块实现全部 git 操作：文件清单、单文件 diff、快照的拍摄、列出、diff 和删除。app 把 acp 的实现注入 kernel。
- desktop 调用这些方法，在 transcript 和「改动」标签中展示。

**Tech Stack:** Rust、tokio、git CLI、gpui-kit 0.10（`Diff`、`DiffState`、`TreeState`、`Clipboard`）、agent-client-protocol 5.5.1。

**Spec:** [Desktop M4b 设计](../specs/2026-11-22-desktop-m4b-design.md)

## Review Focus

1. **快照 anchor 与 desktop 行的 message id 对不上**，卡片就永远不显示。期望：anchor 等于持久化的助手消息 `message_id`，也就是 ACP 推给 desktop 的 `messageId`。由 Task 3 的测试 `end_capture_names_the_last_assistant_message` 固定。
2. **拍快照改动了用户的 index**，例如复制回写，或者用户的 index 不存在。期望：拍快照前后 `.git/index` 的字节完全相同；没有 index 的仓库也能拍。由 Task 4 的测试 `capture_leaves_the_user_index_and_head_alone` 和 `capture_in_a_repository_without_commits` 固定。
3. **工作区是大仓库的子目录**。期望：文件清单和 diff 的路径相对工作区，不含仓库前缀。由 Task 2 的 `git_changes_in_a_subdirectory_are_relative` 和 Task 4 的 `checkpoint_paths_are_relative_to_the_workspace` 固定。
4. **改名的文件**：`-z` 输出里有两个路径。期望：清单里只有一项，类型是 `Renamed`，并带上 `original_path`。由 Task 1 的 `raw_numstat_keeps_a_rename_as_one_change` 固定。
5. **取消或失败的运行**。期望：仍然拍终点快照；起点快照超时的运行不拍终点。由 Task 3 的 `cancelled_run_still_captures_its_end`、`failed_run_still_captures_its_end` 和 `start_timeout_skips_the_end` 固定。注意：`scope.settle` 对失败和「插入前取消」返回 `Err`，所以终点必须在 settle 之前拍，不能依赖 `RunResult`。

```rust
/// Which of a run's two snapshots is taken.
pub enum CheckpointStage { Start, End }

/// One snapshot request: the workspace, the session and run it belongs to,
/// and, for the end, the run's last assistant message.
#[derive(typed_builder::TypedBuilder)]
pub struct CheckpointPoint<'a> {
    pub cwd: &'a Path,
    pub session_id: &'a SessionId,
    pub run_id: &'a RunId,
    pub stage: CheckpointStage,
    #[builder(default)]
    pub anchor: Option<&'a MessageId>,
}

#[async_trait::async_trait]
pub trait RunCheckpoints: Send + Sync {
    /// Snapshots the workspace; a workspace outside Git is skipped with `Ok`.
    async fn capture(&self, point: CheckpointPoint<'_>) -> Result<(), String>;
    /// Removes every snapshot of a session.
    async fn remove(&self, cwd: &Path, session_id: &SessionId) -> Result<(), String>;
}
```

- [ ] **Step 3：实现**

在 `checkpoint.rs` 中定义一个操作结构体，持有 `Option<Arc<dyn RunCheckpoints>>`、`&Arc<Session>`、session_id、run_id，提供两个方法：

- `start(&self) -> bool`：没有注入实现，或者 `session.ownership.is_some()` 时返回 false。否则在 `tokio::time::timeout(START_BUDGET, …)` 中调用 capture。成功返回 true。超时或出错时 `tracing::warn!` 并返回 false。
- `end(&self)`：
  - anchor 用 `session.transcript.inspect_active_branch` 从叶子往根找：先遇到助手消息条目，就用它的 message id；先遇到用户消息条目，就为 `None`。
  - 在 END_BUDGET 内调用 capture，出错只记 warn。

在 `run.rs` 中：

- `record_operation(OperationStarted)` 之后调用 `start()`；
- `scope.execute(…)` 返回之后、`scope.settle(…)` 之前，如果 start 为 true，就调用 `end()`。不管 execute 的结果是 `Ok` 还是 `Err` 都要调用。`RunEnd` 在 settle 中发出，所以 desktop 收到运行结束时，终点快照已经写好。

在 `perform_delete` 中，`store_factory.delete` 成功后，有 cwd 时调用 `remove`，出错只记 warn。

**capture_checkpoint：**

1. 执行 `rev-parse --is-inside-work-tree`。失败时返回 `Ok(false)`。
2. 执行 `git rev-parse --git-path index`，再执行 `--git-path clawcode-checkpoint-index-<nanoid>` 得到临时 index 路径。真实 index 存在时复制过去。
3. 在 `GIT_INDEX_FILE=<临时>` 下依次执行：
   - `git add -A`；
   - `git write-tree`；
   - `git commit-tree <tree> -m <message>`，作者和提交者通过 `GIT_AUTHOR_*`、`GIT_COMMITTER_*` 固定为 `clawcode <clawcode@localhost>`；
   - `git update-ref <refname> <commit>`。
4. 无论成功与否，最后都删除临时 index。

**GitCheckpoints::capture：**

- 取锁的键是 `git rev-parse --git-common-dir` 的规范化路径。
- 提交说明是 JSON：
  - 起点为 `{"runId":…,"startedAtMs":<当前 Unix 毫秒>}`；
  - 终点为 `{"runId":…,"anchorMessageId":…}`。

**checkpoints：**

1. 执行 `git for-each-ref --format=%(refname)%00%(tree)%00%(contents)%00 refs/clawcode/checkpoints/<session>/`。按 `\0` 切成 (refname, tree, contents) 三元组：git 在每条记录后面加换行，所以 refname 要去掉前导换行。然后按运行分组。
2. 去掉起点或终点缺失的运行，以及两者 tree 相同的运行。
3. 剩下的运行执行 `git diff --raw --numstat -z -M --relative <start> <end>`，用 `from_raw_numstat` 解析。
4. 按 `startedAtMs` 升序排列。

**checkpoint_diff：** 执行 `git diff --no-color --no-ext-diff --relative <start> <end> -- <path>`，用 `git_limited` 读取，再交给 `from_git_output`。

**remove_checkpoints：** 对 `for-each-ref` 列出的每个 ref 执行 `git update-ref -d`。

**extension.rs：** 注册两个方法。参数分别是 `CheckpointsParameters` 和 `CheckpointDiffParameters`，按 `root` 构造 `WorkspaceRoot`，错误映射照抄 workspace 方法的写法。
